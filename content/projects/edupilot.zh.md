备课的时间不花在"讲什么"上，花在"把东西做出来"上：找素材、排课件、写教案、改格式。

EduPilot 是教师备课的共创助手。它不停在生成一段文案，而是走完一条闭环——需求和资料进去，课件与教案出来，教师提意见后定向改写，最后按学校要的格式导出。

## 痛点

- **老师要的不是初稿，是能直接上课的东西。** 单轮生成给出一份"还行"的文案之后，排版、局部改写、导出成学校要的格式，全靠人接着做。
- **教师的意见天然是局部的。** "第三页太浅""这段换个例子"——重跑一整条链既慢，又会把已经满意的部分一起改掉。
- **备课资料本来就是多模态的。** 教材是 PDF、课件是 PPT、板书是照片、公开课是视频，工具只收文本就等于没收。
- **长篇内容模型写着写着就散了。** 知识点串讲、学习报告写到中段容易前后矛盾、推导断链，老师还得逐段核对。
- **不同学段、不同进度，讲法完全不同。** 用还没教过的方法讲一道题，等于没讲。

## 系统怎么搭的

五个角色接力，一条链跑完一次备课。

- **五节点主链路。** planner 拆任务 → researcher 找依据 → designer 定结构 → writer 写内容 → coder 出成品，支持首次生成与反馈再生成两种模式。
- **说和打字都行。** 前端同时支持文字与语音输入，浏览器语音识别不可用时自动切换成录音上传、由后端转写兜底。
- **资料和用途绑定着提交。** 哪份材料用在哪个环节由前端指定，而不是把所有材料一股脑塞进上下文。
- **检索范围可切换。** 本地知识库、联网、二者混合三种模式，按课堂场景选。
- **一份中间稿，多种成品。** 主流程先产出结构化中间稿，HTML、PPT、Word、PDF 都从它渲染。
- **进度实时可见，断了能续。** 节点状态实时推送，连接中断后可从断点继续，不用重来。

## 核心难点

- 教师的反馈是局部的，而生成链是整体的——两者的粒度天然不匹配。
- 长文本的逻辑一致性随篇幅衰减，越长越容易自相矛盾。
- 同一道题，讲法必须受当前课程进度约束，而进度这件事不在题目里。
- 数理图形题的信息在图里不在文字里，纯文本链路根本看不见。
- 四种导出格式的排版规则互不相同，稍不注意就会演变成四套并行维护的逻辑。

## 效果

一条从"我要讲什么"到"可以直接上课的成品"的完整链路，中途允许老师随时插话修改，而不是只能推倒重来。

对使用者来说，变化是这些：

- **一次备课在一个界面里走完。** 提需求、传资料、看生成、提意见、导出，不用在几个工具之间来回搬运。
- **提意见就能改，不用重生成。** 说"第三页太浅"，系统只改第三页，其余内容原样保留，改过的地方不会被推翻。
- **手上的资料直接能用。** 教材 PDF、旧课件 PPT、随手拍的板书照片、公开课视频，传上去就能作为依据参与生成。
- **长篇内容不再前后打架。** 知识点串讲和学习报告的推导连贯性、解题步骤拆分的正确率提升约 30%。
- **答案更贴教材。** 按知识点逻辑边界切分资料并配合混合检索后，答题幻觉率下降 55%。
- **图形题能看懂。** 复杂数理图形题自动解析，不用老师再口头描述一遍图。
- **导出即用。** PPT、Word、PDF 一键生成，格式统一，不用再手工调版。

运行状态：多角色协作拓扑稳定支撑 10+ 高并发学生会话场景。

## 技术栈

- **AI 编排** — LangChain、LangGraph；planner / researcher / designer / writer / coder 五节点主链
- **提示工程** — 多步 CoT、Self-Reflection、ReAct
- **检索** — Milvus；按知识点逻辑边界切片，Keyword + Dense 混合检索
- **多模态** — PDF、Word、PPT、图片、视频解析；意图路由的 Vision / Text 联合调度
- **服务** — Python、FastAPI、WebSocket 实时推送
- **产物** — 结构化中间稿统一渲染 HTML / PPT / Word / PDF
- **运维** — Docker
