一份研报要看的东西横跨三种模态：年报是几百页长文本、财务数据锁在表格里、行情是 K 线图、消息面在新闻里。

这个系统把这四路信息收进同一条管道，自动产出初稿与终稿，目标是把研究员从"整理资料"里解放出来。

## 痛点

- **信息横跨三种模态，人工整合一遍要很久。** 而拼接资料这个动作本身不产生任何研究价值。
- **年报太长，检索一旦切错就等于没检索。** 按固定长度切片会把一张表或一段完整论述拦腰截断，取回来的片段没有上下文。
- **表格是重灾区。** 年报里的表格有原生文本表、图片表、跨页表三种形态，任何单一提取方式都会漏掉一部分。
- **数据是活的，研报是死的。** 股价、新闻每天在变，人工写的研报一发布就开始过时。
- **依赖单一大模型不可控。** 接口一抖动，整条流水线跟着停。

## 系统怎么搭的

四路数据进一条管道，两层 Agent 出稿。

- **统一数据管道。** 离线爬公司年报，在线抓新闻资讯与股价，文本、表格、图像收进同一条链路。
- **长文本按文档树组织。** 年报保留章节层级来索引，检索时先定位章节、再取片段。
- **表格三路并取。** RAG、正则、OCR 同时上，结果互相校验补漏。
- **两层 Agent 分工。** 感知 Agent 负责读新闻、K 线图和财报，规划 MultiAgent 负责组稿调度，产出初稿与终稿。
- **模型网关兜底。** ChatGPT、文心一言等多模型统一封装，支持切换与失败重试。
- **异步任务队列。** 离线数据更新与在线生成解耦，互不阻塞。

## 核心难点

- 长文档的语义边界和固定长度的切片边界天然冲突。
- 同一份年报里的表格存在三种物理形态，不存在一种通吃的提取方式。
- 三种模态的信息要在同一段论述里对齐，而它们的时间粒度和可信度并不相同。
- 研报的结论必须可追溯到原文，而生成式模型天然倾向于"顺畅"而非"可查"。
- 上游模型服务的可用性不在自己手里。

## 效果

把"读几百页材料再动笔"压缩成"材料进、初稿出"，研究员的时间从整理资料转移到判断和打磨。

对使用者来说，变化是这些：

- **一次输入，多模态齐活。** 年报、财务表格、K 线图、新闻资讯一起进，不用分别处理再手工拼。
- **拿到的是初稿，不是素材堆。** 系统直接产出成稿结构的研报初稿，再迭代出终稿，研究员在稿子上改而不是从零写。
- **表格数据不再漏。** 三路提取交叉校验，图片表、跨页表都能捞出来，对不上的会暴露出来而不是静默出错。
- **引用能查回原文。** 文档树保留章节层级，结论可以定位回年报的具体位置。
- **数据自动更新。** 离线管道持续刷新年报、股价与新闻，生成时取到的是当前状态。
- **换模型不停机。** 模型网关统一封装调用与重试，某家接口不稳自动切走，业务侧无感。

## 技术栈

- **Agent 系统** — 感知 Agent + 规划 MultiAgent 两层分工
- **模型接入** — AI 模型网关统一封装 ChatGPT、文心一言等多模型，支持切换与失败重试
- **检索** — RAG；文档树结构化索引长文本
- **数据提取** — 正则、OCR、RAG 三路并取并交叉校验
- **数据采集** — 离线年报爬取 + 在线新闻与股价抓取
- **调度** — Celery 异步任务队列，离线更新与在线生成解耦
- **语言与服务** — Python
